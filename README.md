# Citobazar

Платформа вакансій і послуг для Іспанії з архітектурою маркетплейсу. Розділи «Робота» (з підрозділом водіїв CE) і «Послуги агенції» увімкнені на старті, інші вмикаються даними.

| Шар      | Технологія                                     |
| -------- | ---------------------------------------------- |
| Фронтенд | Next.js 16 (App Router, SSR/ISR) + next-intl 4 |
| Бекенд   | FastAPI, SQLAlchemy 2 (async), Alembic         |
| База     | PostgreSQL 16 + PostGIS, pg_trgm, unaccent     |
| Кеш      | Redis                                          |
| Адмінка  | `/admin` у Next.js                             |
| Інфра    | Docker Compose, Caddy, Hetzner                 |

## Структура

```
api/     FastAPI, усі ендпоінти під /v1
web/     Next.js: публічний сайт /{lang}/..., адмінка /admin
infra/   Caddyfile (/v1/* -> api, решта -> web), init-скрипт Postgres
.github/workflows/ci.yml   ruff + pytest, перевірка перекладів + typecheck + build
```

## Мови і URL

- 4 мови, усі під префіксом: `/es`, `/en`, `/ua`, `/ru`. Внутрішній код української `uk` (ISO 639-1): так валідні `hreflang` і `<html lang>`, а в URL стоїть `/ua`. `/uk/...` робить 301 на `/ua/...`.
- `/` робить 302 за cookie `NEXT_LOCALE`, далі за `Accept-Language`, далі на мову за замовчуванням. Пошукові боти завжди отримують `/es`.
- Мова за замовчуванням задається через `NEXT_PUBLIC_DEFAULT_LOCALE`: у розробці `uk`, у проді `es`. `x-default` у hreflang завжди `es`.
- Службові слова шляху перекладені: `/es/empleo`, `/en/jobs`, `/ua/robota`, `/ru/rabota`. Слаг з іншої мови (`/ua/empleo`) робить редирект на слаг своєї мови.
- Перемикач мов веде на еквівалент сторінки, знайдений за сутністю, і зберігає query.
- Інтерфейс перекладено в `web/messages/*.json`, еталон `uk.json`. `npm run check:messages` падає, якщо в якійсь мові бракує ключа.

Статичні сторінки й сторінки агенції описані в [web/src/lib/routes.ts](web/src/lib/routes.ts); розділи, сектори, професії, міста й картки вакансій резолвить `GET /v1/resolve` (див. «Публічні сторінки»).

## Локальний запуск

Потрібні Docker Desktop і Node 22.

```bash
cp .env.example .env            # для розробки: DEFAULT_LOCALE=uk

docker compose up -d            # db, redis, api з hot reload
docker compose exec api alembic upgrade head
docker compose exec api python -m app.cli create-staff --email admin@example.com   # пошта в білий список (адмін)
docker compose exec api python -m app.cli seed-taxonomy
docker compose exec api python -m app.cli import-locations --download   # ~250 МБ джерел, ~1 хв
docker compose exec api python -m app.cli seed-listings                 # демо-вакансії
docker compose exec api python -m app.cli seed-content                  # FAQ, контакти, політика, сторінки агенції
docker compose exec api python -m app.cli recount-seo                   # пороги індексації (далі воркер щогодини)

cd web
cp .env.example .env.local
npm install
npm run dev
```

| Що              | Адреса                                  |
| --------------- | --------------------------------------- |
| Сайт            | http://localhost:3000 (→ /ua)           |
| Іспанська       | http://localhost:3000/es                |
| Адмінка         | http://localhost:3000/admin             |
| Swagger         | http://localhost:8000/v1/docs           |

Фронтенд можна запустити і в контейнері: `docker compose --profile web up -d`.

## Дані (етап 1)

**Таксономія** — [api/seeds/taxonomy.json](api/seeds/taxonomy.json): розділ → сектор → професія, назви й слаги 4 мовами, синоніми, атрибути (CE: тип причепа, ADR, код 95, маршрути, тижні роботи/відпочинку). `seed-taxonomy` оновлює записи на місці (ідентичність: `section.key`, `slug.es` категорії, `key` атрибута). Список секторів треба узгодити з замовником.

**Локації** — `import-locations`:

| Джерело | Що береться |
| ------- | ----------- |
| INE `diccionario25.xlsx` | 19 спільнот, 52 провінції, 8 132 муніципії, коди, офіційні назви |
| INE `pobmun22.xlsx` | населення на 01.01.2022 (новіший файл INE за цією схемою URL не публікує) |
| GeoNames `ES.zip` | координати центру населеного пункту; для Іспанії `admin3` = код INE, тож з'єднання точне |
| GeoNames `alternateNamesV2.zip` | назви en/uk/ru, співофіційні та кастильські варіанти → `aliases` |
| [api/seeds/regions.json](api/seeds/regions.json) | назви та слаги спільнот і провінцій 4 мовами |
| [api/seeds/locations_overrides.json](api/seeds/locations_overrides.json) | екзоніми (València → Valencia), перевірені назви топ-50, нові муніципії без коду в GeoNames |

Правила: слаг з іспанської назви, глобально унікальний; при колізії менший муніципій отримує суфікс провінції (`sancti-spiritus-badajoz`); провінції й спільноти з префіксами `provincia-` / `comunidad-`. Повторний імпорт не змінює існуючі слаги. Звіт імпорту показує збіги за назвою, приблизні координати (La Guijarrosa — точка Santaella) і топ-60 міст для перевірки назв.

Під муніципіями — рівень `localidad`: ~21 тис. сіл, педаній, парафій і районів із GeoNames (без центру муніципію та без об'єктів на кшталт стадіонів). Вони для пошуку/автокомпліту й власної точки оголошення; оголошення та URL прив'язані до муніципію, як у ТЗ.

**Житло** — розділ `vivienda` з секторами «Оренда» (кімнати, квартири, будинки; атрибути: меблі, комунальні, падрон, тварини) і «Тимчасове житло». Розділ вимкнений (`is_enabled: false`), доки не буде запуску житла.

Захист у БД: CHECK на всі 4 переклади, тригер «слаг категорії ≠ слаг локації», максимум 2 рівні категорій під розділом, автоматичний запис старих слагів у `slug_history`.

API: `GET /v1/taxonomy?lang` (кеш 5 хв), `GET /v1/locations/popular?lang`, `GET /v1/locations/{slug}?lang`. Адмінка: `/admin/taxonomy`, `/admin/locations` (пошук за будь-якою назвою, пресет «Топ-50: перевірка назв», фільтр «без uk»).

## Оголошення (етап 2)

Таблиці `listings` + `listing_translations` (розділ 8 ТЗ). Бізнес-правила без БД — [api/app/services/listing_rules.py](api/app/services/listing_rules.py), покриті тестами:

- **зарплата** нормалізується в `salary_monthly_min`: година × 160, день × 21,7, тиждень × 4,33;
- **атрибути** перевіряються за `attribute_definitions` категорії та її сектору (невідомі ключі, типи, значення enum, обов'язкові);
- **статуси**: draft → active ↔ paused; active → expired (воркер) → active (продовження); → closed. `pending`/`rejected` є в схемі на майбутнє;
- **місце**: муніципій або «Вся Іспанія» (`location_scope = spain_wide`). Можна обрати село — тоді оголошення прив'язується до його муніципію, а точкою для радіуса стає село;
- **переклади**: текст мовою оригіналу обов'язковий; слаг `{назва}-{місто}`, публічний URL додасть `-{id}`.

Права (BOLA): адміністратор змінює все, менеджер — лише свої оголошення; дублювати може будь-яку (копія стає чернеткою автора).

Воркер `worker` (APScheduler) кожні 10 хв переводить прострочені в `expired`; вручну: `python -m app.cli expire-listings`.

Адмінка `/admin/listings`: список із фільтрами, форма з табами мов, динамічними атрибутами категорії, пошуком міста/села, прев'ю картки; дії «опублікувати / призупинити / відновити / продовжити / закрити / дублювати / видалити чернетку».

API: `/v1/admin/listings` (CRUD, `/actions`), публічно `GET /v1/listings?lang&section&category` і `/v1/listings/stats` (етап 3 додасть фільтри, фасети й пошук).

Демо-дані: `python -m app.cli seed-listings` — 20 вакансій і послуга з [api/seeds/listings_demo.json](api/seeds/listings_demo.json) (різні мови, «вся Іспанія», чернетка, призупинена, прострочена).

## Пошук і фільтри (етап 3)

Код — [api/app/search/](api/app/search/). API й сторінки залежать лише від протоколу `SearchBackend` ([backend.py](api/app/search/backend.py)); реалізація на Postgres — [postgres.py](api/app/search/postgres.py), підміна на Meilisearch — в одному місці (`get_backend`).

- **Пошуковий документ** `listing_search` (міграція 0005): заголовки, опис, назви й синоніми професії та сектору, назви й аліаси міста. es → `spanish`, en → `english`, усе разом ще й `simple + unaccent` (для uk/ru і точних збігів). Перебудовується тригерами БД при зміні оголошення, його текстів, категорії чи локації.
- **Запит**: токени в усіх конфігураціях, останній — префіксом (`:*`); якщо FTS дав < 5 — добираємо триграмами (`trgm_text %> q`, поріг 0.5 для `word_similarity`, ТЗ називає 0.3 для `similarity`).
- **Розуміння запиту** ([understanding.py](api/app/search/understanding.py)): «водій се мадрид» → професія + місто (кириличні «се» = CE), сторінка редиректить на фільтри без `q`. Відоме обмеження: відмінки назв міст («в Малазі») не розпізнаються — такі запити потрапляють у `search_misses`.
- **Фільтри в URL** ([params.py](api/app/search/params.py)): ярус 2 (`salary_min`, `housing`, `no_language`, `no_experience`, `schedule`, `contract`, `posted`, `radius`), ярус 3 `a.<key>` лише для атрибутів обраної категорії, `q`, `sort`, `page`. Невідоме відкидається, ключі й значення сортуються → `canonical_query`; сторінка робить постійний редирект (Next.js віддає 308, для пошуковиків це те саме, що 301).
- **Фасети** диз'юнктивні: один SQL з `COUNT(*) FILTER (...)` на кожне значення + лічильники професій і міст; кеш Redis 60 с, скидається версією при зміні оголошень.
- **Місце**: муніципій (або радіус від нього), провінція, спільнота; оголошення «вся Іспанія» — в кожній видачі після місцевих.
- **Порожня видача**: варіанти ослаблення з кількістю (без атрибутів → більший радіус → провінція → вся Іспанія) + форма «Підібрати роботу».
- **Автокомпліт** `GET /v1/suggest?q&lang`: професії, міста (спершу з вакансіями), «професія · місто» з кількістю; кеш на (мова, префікс) 10 хв.
- **Журнал** `search_misses` → адмінка «Пошук без результатів».

API: `GET /v1/listings?lang&section&category&location&...` (список + фасети + canonical_query), `GET /v1/suggest`, `GET /v1/search/understand` (для налагодження).

Сторінки: `/ua/robota`, `/ua/posluhy`, `/ua/posluhy/dokumenty`; з етапу 4 професія, місто й «з житлом» — у шляху, решта фільтрів — у query.

| Режим | p50 | p95 | p99 |

Під 16 паралельних запитів на 2 воркерах упираємося в пропускну здатність (~80 req/s) — це питання кількості воркерів і заліза, не запитів.

## Заявки «отримати дзвінок менеджера»

Форма на головній (після банера водіїв) і на сторінці `/ua/vodiiam-ce` (там професія CE підставляється автоматично). `POST /v1/applications` без реєстрації:

- телефон нормалізується в E.164 (`612 345 678` → `+34612345678`, номери без коду вважаються іспанськими);
- обов'язкова згода, зберігається `consent_at` і версія політики;
- не більше 5 заявок на годину з IP (Redis);
- той самий телефон + та сама вакансія/категорія за 24 год → не нова заявка, а нотатка до існуючої;
- UTM-мітки зі сторінки зберігаються.

Адмінка: `/admin/applications` — список, фільтр і зміна статусу. Етап 5 додасть Turnstile, сповіщення в Telegram-групу, бота, призначення менеджера, нотатки й CSV.

## Публічні сторінки (етап 4)

**Шлях**: `/{мова}/{розділ}/{сектор?}/{професія?}/{житло?}/{місто|provincia-…|comunidad-…?}`, картка — `/{мова}/{розділ}/{vakansiia|oferta|job|vakansiya}/{слаг}-{id}`. Приклади: `/ua/robota/transport/vodii-ce/madrid`, `/ua/robota/z-zhytlom/valencia`, `/es/empleo/con-alojamiento`.

- **Резолвер** [api/app/seo/resolver.py](api/app/seo/resolver.py), `GET /v1/resolve?lang&path`: 301 для старого слага (`slug_history`), слага іншої мови, професії без свого сектору, застарілого слага картки; вимкнений розділ (житло) → 404.
- **«Робота з житлом»** — не розділ, а параметр шляху (`z-zhytlom` / `con-alojamiento` / `with-housing` / `s-zhilyom`); вкладка в шапці й фасет «З житлом» перемикають сегмент. Розділ оренди житла лишається вимкненим.
- **Пороги індексації** ([rules.py](api/app/seo/rules.py), таблиця `seo_pages`): розділ — завжди; сектор, професія — від 1 активної вакансії; з містом або житлом — від 3. Якщо вакансій стало менше, сторінка ще 14 днів індексується (`below_since`). Перерахунок — воркер щогодини, після дій з вакансіями в адмінці, `cli recount-seo`. Адмінка `/admin/seo`: стан, фільтри, власні title/description.
- **Фільтри в query** → `noindex, follow` + canonical на сторінку без query; пагінація `?page=N` індексується. Старі посилання `?category=&location=&housing=` редиректять у шлях одним 301.
- **Картка**: закрита — 200 з плашкою «Вакансію закрито» (без JobPosting); через 30 днів — `noindex`; через 90 — 410 (перевіряє proxy через `GET /v1/listings/{id}/state`). Індексується лише мовами, якими є текст; hreflang — тільки на ці мови.
- **hreflang** на всіх сторінках (x-default = es), **JSON-LD**: JobPosting + BreadcrumbList (картка), BreadcrumbList + ItemList (списки), FAQPage.
- **Sitemap**: `/sitemap.xml` (індекс) → `/sitemaps/{ua|es|en|ru}-static.xml`, `-lists-N.xml`, `-listings-N.xml` по 40 тис. URL з `xhtml:link`.
- **Мобільна панель фільтрів**: bottom sheet із «Показати N», лишається відкритою між кліками по фільтрах.
- **Сторінки агенції**: `/ua/vodiiam-ce`, `/ua/posluhy/kod-95`, `/ua/posluhy/obmin-prav` (тексти в `content_blocks`, форма з підставленою послугою). **Статичні**: розмістити вакансію (заявка роботодавця → `employer_requests`), контакти, FAQ, політика (noindex; текст — шаблон, потрібна вичитка юристом).

Тексти статичних сторінок — [api/seeds/content.json](api/seeds/content.json) (uk + es; інші мови падають на es).

## Дизайн (ТЗ §11)

Світла тема: білий хедер, фон `#F6F2EA`, текст `#16181D`, акцент `#FF6A1A` лише з темним текстом (акцентний текст на світлому — `#C2521A`). Шрифти Onest (текст) і Unbounded 500 (логотип, H1), самохостяться через `next/font`. Темні лише плитка з площею, банер і сторінка водіїв CE.

- Головна: hero з пошуком «що + де» і 4 популярними запитами, одразу під ним каталог вакансій з фільтрами (фільтри ведуть на індексовані сторінки розділу), далі банер водіїв і заявка. На телефоні площа прихована, щоб каталог був одразу після пошуку.
- Картка в списку: зарплата — найпомітніший елемент, далі заголовок, «компанія · місто · час», до 3 тегів, ♡ і «Відгукнутися».
- Мобільний: нижнє меню (Головна, Пошук, Збережене, Кабінет), фільтри — bottom sheet.
- Стилі: [web/src/styles/](web/src/styles/) — `base.css` (токени, кнопки, форми), `site.css` (хедер, пошук, картки, каталог), `pages.css` (картка вакансії, агенція, заявка), `admin.css`.

## Обране, відгуки, кабінет (частина етапу 6)

Поки без входу: обране (♡) і відправлені відгуки зберігаються в браузері ([web/src/lib/saved.ts](web/src/lib/saved.ts)), синхронізуються між вкладками. Після відгуку кнопка на картках стає «Відгук надіслано», на сторінці вакансії — плашка «Ви вже відгукнулися…». Кабінет `/ua/kabinet` (noindex): вкладки «Збережене» і «Мої відгуки», картки тягне `GET /v1/listings/cards?ids=&lang=` (лише активні; закриті показуються як «більше не доступна»). Лічильник обраного — на ♡ у хедері й у нижньому меню.

Далі (потрібні ключі): вхід через Google Identity Services і Telegram Login Widget, перенесення обраного й історії з браузера в акаунт, видалення акаунта.

## Послуги агенції

Розділ «Послуги» (`sections.kind = services`) — не оголошення, а постійні послуги агенції: документи (обмін прав, NIE/TIE, падрон) і навчання (код 95, права C/CE). Сторінки: каталог `/ua/posluhy`, сфера `/ua/posluhy/dokumenty`, послуга `/ua/posluhy/obmin-prav` (завжди індексуються, є в sitemap). Текст послуги — блок `service_<es-слаг категорії>` у [seeds/content.json](api/seeds/content.json): `title`, `body`, `data.summary` (картка в каталозі), `data.points` («Що входить»); без блоку показується короткий загальний текст. Заявка з цієї сторінки прив'язана до послуги (для статистики й розподілу заявок). Вакансію в категорії послуги створити не можна (форма їх не показує, API відповідає 422).

## Теги вакансій

Крім атрибутів професії (водій CE: причіп, ADR, код 95…), у розділу є **теги** — атрибути з `section_id` у `attribute_definitions`, описані в [seeds/taxonomy.json](api/seeds/taxonomy.json) (`sections[].attributes`). Вони діють у всьому розділі: поле у формі вакансії («Теги вакансії»), фільтр ярусу 2 на сайті (`a.<key>` у query, noindex), рядок на сторінці вакансії. Новий тег — це дані, не код. Ключ тегу не може збігатися з ключем атрибута професії (обидва лежать у `listings.attributes`).

Теги «Роботи»: підходить для (студентам, пенсіонерам, парам і сім'ям, людям з інвалідністю), говоримо (українською, російською), рівень іспанської / англійської (A1–C2), документи (тимчасовий захист, допомога з NIE/TIE, потрібен дозвіл на роботу), житло безкоштовне / платне, роботодавець забезпечує (харчування, транспорт, дорога, спецодяг), офіційне оформлення, без освіти, права B, власне авто. «Робота на кеш» і теги за статтю чи віком свідомо не додані (іспанське законодавство).

Правило перекладу: усе з фіксованими значеннями (теги, період зарплати, житло, графік, професії) перекладене в довідниках і показується мовою відвідувача автоматично; вільний текст вакансії (назва, опис, вимоги, умови) вставляється вручну окремо для кожної мови, автоперекладу немає.

Водій CE: крім маршрутів (по Іспанії / міжнародні) — країни рейсів (з'являються у формі, коли обрано «Міжнародні»).

Поля набору у вакансії: кількість місць, дата старту, тривалість у місяцях, «Терміново» (позначка на картці). Публікація — лише з іспанською версією тексту (ТЗ адмінки §6), чернетку можна зберегти будь-коли. Без зарплати форма попереджає, але публікувати дозволяє.

## Адмінка: мови

Інтерфейс адмінки — українська, російська, англійська, іспанська; кожен співробітник обирає свою мову перемикачем у меню (cookie `admin_locale`, окремо від мови сайту). Тексти — [web/messages/admin/](web/messages/admin/) `<мова>/<екран>.json`, `npm run check:messages` перевіряє, що в усіх мовах однакові ключі. API повертає коди помилок (`publish_needs_es`, `attr_value:trailer_type`…), адмінка показує їх обраною мовою; назви професій, міст і тегів приходять мовою адмінки (`Accept-Language`).

У вакансії немає «мови оригіналу»: усі 4 мови рівноправні, текст кожною вставляється окремо. Там, де потрібної мови немає, сайт показує іспанську, а якщо її ще нема — першу заповнену (EN, UA, RU).

## Адмінка: доступ (ТЗ адмінки §1)

- **Вхід лише через Google**, паролів немає. Бекенд перевіряє підпис ID-токена, аудиторію (`GOOGLE_CLIENT_ID`), видавця й підтверджену пошту, далі — пошту в білому списку (`users` з роллю `manager`/`admin` і увімкненим доступом). Чужа пошта отримує 403, навіть якщо вхід у Google успішний. Перший вхід прив'язує Google-акаунт (`google_sub`): інший акаунт з тією ж поштою не пройде.
- **Сесії** 30 днів у таблиці `user_sessions` (у базі лише SHA-256 токена). Cookie `httpOnly`, `SameSite=Lax`. «Вийти на всіх пристроях» — у меню; адмін може закрити сесії будь-кого на екрані «Користувачі».
- **CSRF**: API приймає сесію лише в заголовку `Authorization` (сервер Next.js додає його з cookie), cookie API не читає; `proxy.ts` відхиляє будь-який змінювальний запит до `/admin` без `Origin` свого сайту; серверні дії Next.js додатково звіряють `Origin` з `Host`.
- **Ролі**: менеджер — заявки, кандидати, вакансії, роботодавці, експорт; адмін — ще довідники, контент, SEO, користувачі, GDPR. Перевірка на кожному ендпоінті: весь `/v1/admin` закритий для не-персоналу на рівні роутера, адмінські ендпоінти мають `require_admin`; тест проходить усі `/v1/admin`-операції без сесії й чекає 401.
- **Вимкнення доступу** — перемикач на екрані «Користувачі»: людина не видаляється (ім'я лишається в нотатках), її сесії закриваються одразу. Собі адмін не може вимкнути доступ чи зняти роль.
- **Журнал**: кожна зміна в `/v1/admin` пишеться в лог сервера з `user_id` (`bazarcito.actions`); ліміт 20 спроб входу за 10 хв з IP.
- **Локально без Google**: `ADMIN_DEV_LOGIN=true` (за замовчуванням у `docker-compose.yml`) показує на сторінці входу форму «Увійти без Google» для пошти з білого списку. У продакшні API з цим прапорцем не стартує.
- **Налаштування Google**: Google Cloud Console → APIs & Services → Credentials → OAuth client ID, тип «Web application»; в «Authorized JavaScript origins» — домен сайту і `http://localhost:3000`. Client ID — у `GOOGLE_CLIENT_ID` (`.env`), секрет не потрібен.
